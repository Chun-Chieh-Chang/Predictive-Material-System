## 4. IDE 工具整合機制分析

### 4.1 Trae AI（當前使用的 IDE）的自動觸發機制

```
Trae AI（Agnes）執行 git 命令時：
    │
    ├── git commit ──────→ OS 觸發 .husky/pre-commit ──→ 檢查通過則提交
    │                                                      ↑ 自動
    ├── git push ────────→ OS 觸發 .husky/pre-push ──→ 檢查通過則推送
    │                                                      ↑ 自動
    └── git push → master ──→ GitHub 觸發 .github/workflows/* ──→ CI/CD 自動運行
                                                             ↑ 自動
```

**驗證結果：**

| 觸發點 | 機制 | Trae AI 是否自動觸發 | 是否需要手動配置 |
|--------|------|----------------------|------------------|
| `git commit` → pre-commit | OS 層 Git hook | ✅ 是（只要 Husky 已安裝） | ❌ 否 |
| `git push` → pre-push | OS 層 Git hook | ✅ 是（只要 Husky 已安裝） | ❌ 否 |
| `push → master` → GitHub Actions | GitHub 事件驅動 | ✅ 是（只要 workflow 存在） | ❌ 否 |
| `daily-scan` scheduled | GitHub Actions cron | ✅ 是（只要 workflow 存在） | ❌ 否 |

**核心發現：** 所有觸發點均為 **OS/GitHub 層級的自動機制**，Trae AI 作為 IDE 不會介入或阻擋這些 hook。只要專案正確配置了 Husky 與 GitHub Actions，**任何使用 Trae AI 的開發者執行 `git commit` / `git push` 時，檢查都會自動執行**，無需手動操作。

### 4.2 VS Code / Cursor / JetBrains IDE 的相同行為

上述分析同樣適用於 VS Code、Cursor、JetBrains WebStorm 等基於 Git 的 IDE：

```
任何支援 Git 的 IDE：
    使用者執行 Commit/Push 操作
        ↓
    IDE 呼叫 git commit/push 命令
        ↓
    OS 觸發 .husky/ 下的 hook 腳本
        ↓
    hook 腳本執行檢查
        ↓
    通過 → 繼續操作 / 失敗 → 顯示錯誤訊息並中止
```

**結論：此機制是 Git 原生行為，與 IDE 無關。**
