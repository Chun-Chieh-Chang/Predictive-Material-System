# CAPA-015 報告：介面虛假擺設與 Mock 數據清理及防禦機制 (Anti-Placebo & Zero-Mock UI)

> **編號**：CAPA-015  
> **日期**：2026-08-24  
> **責任人**：Antigravity (Senior Full-Stack Architect)  
> **狀態**：✅ 已實裝驗證 (Verified in Production)  
> **影響等級**：中（消除 UI 虛假資訊與誤導性 Fallback 數據，建立零偽造規範）

---

## 1. 問題描述

- [✗] **Navbar 靜態連線卡片**：原頂部常駐「🟢 內網伺服器連線中」，背後無任何網路/後端心跳連線狀態監聽，為純前端靜態 Mock 裝飾。
- [✗] **SalesWorkbench 假數據 Fallback**：業務工作台在查詢無預測記錄或無訂單之料號時，預設 fallback 至偽造之假數據（`10,000` / `8,500` / `-15%` / 假建議），未真實呈現空狀態。
- [✗] **ProcurementWorkbench 推估交期未明確標註**：無訂單料號以 `今日 + 20天` 模擬交期推算倒數，介面未明確標示為推估值。

---

## 2. MECE 六大維度根因分析 (RCA)

- [✗] 既有問題：介面存在無真實數據流支持的靜態連線燈與查詢無資料時的偽造 Mock Fallback 數值。
- [✓] 分析目標：以 MECE 六大維度窮盡排查技術、流程、工具、測試、文檔與環境原因。

【技術層面】
- [✗] 原型開發時期為營造企業級儀表板氛圍，遺留了靜態連線標籤與 Mock fallback 數據，未在功能上線前徹底清除。
- [✓] 矯正：徹底移除 Navbar 無效連線標籤，將各工作台 Fallback 改為真實空狀態（0 筆 / 空提示）。

【流程層面】
- [✗] 缺乏「Zero-Mock UI」的強制審查門禁，使得開發過程中為了畫面美觀而塞入無效或誤導性的視覺擺設。
- [✓] 矯正：建立零偽造規範，任何無心跳或無真實資料之視覺元件一律禁止上線。

【工具層面】
- [✗] 代碼靜態分析未限制 Mock 物件在生產視圖中的使用。
- [✓] 矯正：於靜態檢查中納入空狀態與真實 Fallback 模式驗證。

【測試驗證層面】
- [✗] 單元測試著重於有資料時的運算正確性，忽略了「查無資料」或「邊界條件」時是否真實呈現空狀態。
- [✓] 矯正：增加查無資料邊界測試，確認 Empty State 渲染無偽造數值。

【文檔層面】
- [✗] 規範中未明確寫入「禁止任何無實質功能的 UI 擺設」之條款。
- [✓] 矯正：於 `AGENTS.md` 與 `GEMINI.md` 寫入第 5 條「零偽造與嚴禁虛假 UI 擺設 (Zero-Mock & Anti-Placebo UI)」。

【環境層面】
- [✗] 本系統本質為純前端 Client-Side SPA（本地運算 / LocalStorage / Excel 離線解析），並無常駐後端伺服器，不應出現「伺服器連線中」等與架構不符之字眼。
- [✓] 矯正：介面文字全面對齊純前端單機離線與檔案交換架構。

- [✓] 核心工程規範沉澱：已將 **「零偽造與嚴禁虛假 UI 擺設 (Zero-Mock & Anti-Placebo UI)」** 寫入專案核心工程規範 `AGENTS.md` 與 `GEMINI.md` 第 5 條。
