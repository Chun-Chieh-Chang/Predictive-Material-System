# CAPA-001 報告：Navbar 連線狀態日期硬編碼問題 (Hardcoded Date String in Navbar)

> **責任人**：Antigravity (AI Senior Architect)  
> **關聯 Commit**：含於 V-20260821-22 優化批次 (`2ecbe7b`)  
> **狀態**：✅ 已關閉 (Closed)

---

## 1. 問題描述

- [✗] `Navbar.tsx` 中的連線狀態指示器顯示的日期（`2026-08-20`）為硬編碼靜態字串，並非動態計算的即時日期。
- [✗] 當跨天使用系統時，Navbar 日期不會自動更新，導致使用者看到過期的日期資訊。

---

## 2. MECE 六大維度根因分析

- [✗] 既有問題：Navbar 連線狀態日期為靜態字串，跨天不更新。
- [✓] 分析目標：以 MECE 六大維度窮盡排查技術、流程、工具、測試、文檔與環境原因。

【技術層面】
- [✗] 初版開發時以靜態字串快速佔位實作（`const date = '2026-08-20'`），未替換為動態日期計算。
- [✓] 已改為使用 `TaiwanDate` 元件，透過 `useState` + `useEffect` 實現即時日期顯示，每 30 秒檢查是否跨天並自動更新。

【流程層面】
- [✗] 缺乏佔位符清理 SOP：快速原型開發結束後，未安排統一的佔位符替換巡查。
- [✓] 納入全域程式碼清理 SOP 的檢查清單，避免佔位程式碼殘留至正式環境。

【工具層面】
- [✗] 無自動化靜態字串偵測工具，無法自動發現硬編碼日期。
- [✓] 由日常 Code Review 覆蓋此類低風險問題。

【測試驗證層面】
- [✗] 未對 Navbar 日期顯示進行跨天測試。
- [✓] 修復後已確認跨天場景下日期可正確切換。

【文檔層面】
- [✗] 未在開發文件中標記此處為佔位實作。
- [✓] 已於 `DEV_LOG.md` 記錄此 CAPA。

【環境層面】
- [✓] 純前端元件，無環境依賴性問題。
