兩大核心主軸：簡易流程與數據邏輯（一分鐘版）

主軸一：原物料備料補貨——「要叫多少料？何時叫？」從需求反向扣掉手上有的，算出原料缺口與最晚下單死線：

① 算需求 總需求 = 預估量 + 實單量（四種彙總模式擇一） ② 扣成品供給 成品缺口 = Max(0, 總需求 − 良品在庫 − WIP待驗×良率) ③ 展開用料 原料毛需求 = 缺口 × 單穴克重 ÷ 1000 ÷ (1−損耗率) ④ 扣原料供給 原料淨需求 = Max(0, 毛需求 − 有效在庫 − 在途量 + 安全庫存×係數) ⑤ 產生建議 淨需求 ＞ 0 才觸發補貨 → 進位至 MOQ 倍數 最晚下單日 = 需求交期 − 採購交期（海運 90~150 天）

三道預警：紅 距最晚下單日 ≤ 15 天（負值＝已逾期）黃 備太多（＞需求 1.6 倍）橘 超倉容（＞12,000 KG，自動建議分批到貨）

主軸二：產品交期估算——「這張訂單來得及交嗎？」以客戶約定交期為基準，反向體檢五段時間，不及格的環節亮燈：

① 拆訂單 成品缺口 = 訂單量 − 現貨 − WIP有效 ② 產能體檢 所需生產天數 = ⌈缺口 ÷ 日產能⌉ ＞ 距交期天數？→ 紫燈 ③ 齊套體檢 原料來不及下單？→ 紅燈（沿主軸一同一套計算） ④ 物流體檢 海運交期倒推＋在途船期延誤？→ 橘燈 ⑤ 綜合評分 緊張指數：紅 95／紫橘 75／黃藍 50／正常 10，由高到低排序出清單

兩條流程共用同一條計算脊：成品缺口 → 單穴克重 → 毛需求 → 淨需求 → 最晚下單日（完整推導見第 4 節）。設計鐵律：主檔缺值即拒算（寧可不算不亂算）、在途只算沒到貨的、推估值必標示。

常見問題（FAQ）

Q1：畫面出現「主檔缺值、無法計算」是壞掉了嗎？

不是。系統的原則是「寧可不算，也不亂算」——某個品號的基本資料（良率、損耗率、採購交期等）沒有維護完整時，系統拒絕推估並明確告訴你缺什麼。請至「資料表維護」補齊後重新計算。

Q2：為什麼建議採購量比實際缺口還多？

兩個原因：①供應商有最小起訂量（MOQ），不足一包裝倍數會自動進位；②系統會加上安全庫存當作防護水位，避免突發狀況無料可用。

Q3：「最晚下單日」已經過了（紅色預警），該怎麼辦？

代表照正常程序已來不及。系統建議：即刻開立採購單並評估改空運、要求供應商提早到港，或與客戶協調分批／延後交貨。

Q4：系統算出來的交期，是對客戶的承諾嗎？

不是。交期估算是一種「體檢」：以客戶要求的日期為基準，反推原料、產能、物流各環節來不来得及，提前告訴你哪裡會卡關。對客戶的承諾仍由業務依體檢結果判斷。

Q5：安全庫存是誰決定的？可以調整嗎？

基本值由每個原料品號在主檔中個別維護；系統另提供全廠一致的「安全庫存係數」（預設 1.0 倍），可在系統設定中整體調高或調低，例如旺季調到 1.25 倍。

Q6：為什麼同一個產品，不同時候建議備料量不一樣？

同一產品可能有多副模具，各模具的耗料與產能不同。系統依「多模備料策略」（預設採最耗料的保守原則）選模計算，策略或模具現況（如塞穴）改變，建議量就會跟著變。

03需求彙總邏輯（四種模式）

業務預估與實際訂單如何合併計算（四種策略）

系統將「客戶預估（Forecast）」與「實際訂單（PO）」合併為總需求時，由全域參數 demandConsumptionMode 決定彙總方式：

模式代碼運算式說明與適用情境
additive（預設）總需求 = 預估量 + 實單量預估視為尚未下單之未來需求，與已下單量累加。保守備料，適合客戶「預示＋分批落單」型態。
po_consume總需求 = Max(預估量, 實單量)實單自預估中沖銷（消耗），取兩者較大者。適合「預估為總額上限、訂單逐筆吃掉預估」的客戶。
actual_only總需求 = 實單量完全只信賴實際訂單，忽略預估。
forecast_only總需求 = 預估量完全只信賴客戶預估，忽略實單。
補充：所有 MRP 計算均排除已取消（cancelled）狀態之訂單；在途 PO 亦排除已到達（arrived）與分批到達（partial_arrived）狀態，避免重複計入可用供給。

4.3 整合可行性結論#

  • 文件層級：已完成整合。第 5、6 節兩張流程圖的重疊段落均引用同一組公式與同一份參數定義表（5.3 節），認知上已是單一統一邏輯，杜絕「兩份文件兩套說法」的矛盾風險。
  • 程式碼層級：評估為「可抽共用核心，但不建議現階段強行合併」。理由：(1) 觸發主體不同（SKU×版本 vs 逐筆訂單），迭代語意不同；(2) 選模策略與容差處理存在刻意設計之差異（見上表），合併需引入大量條件分支反而提高複雜度；(3) 輸出契約不同（採購建議 vs 瓶頸診斷），硬合一將違反單一職責原則並冒穩定性風險。
  • 未來重構建議：若後續出現第三個消費端（如進階排程模組），可將計算脊抽出為純函式 computeCoreRequirement(db, demandQty, targetDate, bom, params)，回傳「缺口／毛需求／淨需求／建議量／最晚下單日」結構，由兩引擎各自消費並保留差異化外殼。此重構屬低風險、高報酬，惟需搭配既有端到端模擬測試套件回歸驗證後方可實施。

5.2 流程逐步說明#

  • ① 需求彙總：取該品號最新版（或指定版本）預估與有效實單，依四種模式合併為總需求（詳第 3 節）。已取消訂單一律排除。
  • ② 主檔缺值校驗（缺值即擋）：成品缺 std_sorting_yield、BOM 缺 std_mfg_scrap_rate、原料品號不存在或缺「交期／MOQ／安全庫存」任一欄位時，立即終止並回傳紅色警示，禁止以全域預設值頂替（0 為合法值，不會誤判為缺值）。
  • ③ 成品淨需求：Max(0, 總需求 − 成品良品在庫 − WIP待驗 × 標準良率)，快照取最新結算日。
  • ④ 多模選模：一品號綁多副模具時依 multiMoldStrategy 三策略擇一（保守最重／最輕克重／僅主模），亦可人工指定。
  • ⑤ 單穴克重與日產能：塞穴聯動——妥善穴數減少時克重自動上升、日產能同時下降，屬數學自動聯動。
  • ⑥ 毛需求：缺口換算重量後除以 (1 − 損耗率) 放大，涵蓋成型損耗。
  • ⑦ 色母拆分：配比 ＞ 0 時，BOM 之 rm_sku 代表色母，總毛需求拆為基礎樹脂與色母兩條獨立鏈路各自計算後匯流（詳第 10 節）。
  • ⑧ 虛擬預扣：enableVirtualBackflush 開啟時，先預扣 WIP 待驗品已耗用之原料，消除 ERP 月底扣帳時序差造成的月中庫存高估。
  • ⑨ 有效供給盤點：有效在庫 = Max(0, 帳面在庫 − 虛擬預扣)；在途量僅計狀態非 arrived / partial_arrived 之 PO。
  • ⑩ 安全庫存水位：原料品號主檔之 safety_stock_kg × 全域係數 safetyStockMultiplier，作為淨需求的加回項。
  • ⑪ 補貨觸發判斷：淨需求 = 毛需求 − 有效在庫 − 在途 + 安全庫存；僅當淨需求 ＞ 0 時觸發補貨，否則判定庫存充足免採購。
  • ⑫ 採購量與前置期倒推：建議量無條件進位至 MOQ 整數倍；最晚下單日 = 需求交期 − lead_time_days。
  • ⑬ 前置期校驗與缺料預警：距最晚下單日 ≤ shortageAlertBufferDays（預設 15 天）即發紅色缺料警戒；負值代表下單已逾期，需即刻開 PO 或改空運。
  • ⑭ 超備與爆倉檢查：(帳面在庫＋在途) ＞ 毛需求 × overstockMultiplier 且 ＞ 安全庫存 × 1.5 ➜ 黃色超備呆滯；(帳面在庫＋在途) ＞ defaultWarehouseCapacityKg ➜ 橘色爆倉。
  • ⑮ 大批次分批調度：建議量 ＞ 倉容 × 0.6 或 ≥ 5,000 KG 時自動拆兩批——首批 50%（進位至 MOQ）於需求交期到港，次批間隔 30 天，兼顧倉容壓力與資金積壓。

6.2 流程逐步說明#

  • ① 訂單量拆解（三層供給剝離）：對每筆有效訂單（排除 cancelled）依序剝離「成品良品在庫 → WIP 有效量（待驗 × 標準良率）」，剩餘即成品缺口 fgGap = Max(0, 訂單量 − 現貨 − WIP有效)。此為後續所有時間估算的需求基準。
  • ② 主檔缺值攔截：成品缺良率、BOM 未建立或缺損耗率、原料品號不存在或缺採購三要素時，強制在診斷結果最前方插入紅色「⚠️ 主檔缺值」項目，並標明本單診斷數字不可作為決策依據。
  • ③ 產能負荷核算：以主模 BOM（is_primary_mold 優先）之妥善穴數與成型週期計算日產能，再得所需連續生產天數 requiredProdDays = ⌈fgGap ÷ 日產能⌉。
  • ④ 生產週期疊加與異常緩衝配置：MRP 層級之產能瓶頸判定含安全裕度——requiredProdDays + capacityBufferDays ＞ 距交期天數 即發紫色預警（buffer 預設 0 天，抗斷線情境可調至 3 天）；訂單診斷層級則以 requiredProdDays ＞ daysToDeliver 直接判定產能赤字，另偵測模具 maintenance 維修狀態。
  • ⑤ 原物料齊套時間校驗：沿備料計算脊（毛需求 → 虛擬預扣 → 淨需求）推導原料缺口，並以「最晚下單日 = 交期 − lead_time_days」校驗齊套可行性——淨需求 ＞ 0 且距最晚下單日 ≤ shortageAlertBufferDays 即紅燈（負值＝已逾期，原料不可能如期齊套）。
  • ⑥ 物流配送時間核算：國外海運交期（典型 90~150 天）已內化於 lead_time_days 倒推邏輯；另逐筆掃描在途 PO 狀態，存在 delayed 船期延誤時發橘燈風險提示。
  • ⑦ WIP 全檢環節：現貨不足但「現貨＋有效 WIP」足夠 ➜ 黃燈，需品保及時全檢入庫；總供給仍不足 ➜ 紅燈實質缺貨赤字，須緊急開機或協調延後交貨。
  • ⑧ 色母配色環節：配比 ＞ 0 時以快速式 毛需求 × 配比 ÷ (100 + 配比) 推估色母需求，大於有效樹脂在庫即藍燈缺料。
  • ⑨ 綜合緊張指數評定：六環節燈號映射為 tensionScore（0~100）：任一紅 = 95（危急）；紫或橘 = 75（高度）；黃或藍 = 50（中度）；皆無 = 10（正常）。清單按分數由高至低排序輸出行動建議。

07三階 MRP 核心引擎（成品 → 模具 → 原料）

完整公式推導（工程師／顧問深度參考）

MRP 引擎（mrpEngine.ts → calculateMRPForSKU）針對單一成品 SKU，依最新（或指定）版本之預估需求執行三階段推導（即第 5 節圖 A 之計算脊）：

Phase 1｜成品淨需求（FG Net Requirement）#

WIP 有效量 = WIP 待驗量 × 標準全檢良率 (std_sorting_yield) 成品淨需求 = Max( 0 , 總需求量 − 成品良品在庫 − WIP 有效量 )
  • 總需求量依第 3 節之四種彙總模式決定。
  • 版本規則（多版本支援）：同一品號之預估可存在多個版本（version_no）。未指定版本時取最新版——以 created_at 降序、次以 version_no 降序判定，不依賴資料列插入順序；MRP 計算機提供版本下拉切換，並附「版本衝擊分析」（現版 vs 前一版之需求與採購建議差異，相同模具與系統參數下重算）。
  • 良品在庫與 WIP 待驗量取自最新日期之庫存快照。
  • Anti-Placebo 保護：若品號主檔缺 std_sorting_yield，該 SKU 直接回傳紅色「無法計算」警示，禁止靜默帶入預設值偽裝成有效運算。

Phase 2｜BOM 展開與原料毛需求#

單穴克重 Unit_Weight_g = ( 整模淨重 net_mold_weight_g + 流道重 runner_weight_g ) ÷ 妥善穴數 active_cavities 原料毛需求 KG = ( 成品淨需求 PCS × 單穴克重 g ÷ 1000 ) ÷ ( 1 − 成型損耗率 std_mfg_scrap_rate )
  • 一個成品可能綁多副模具（多筆 BOM），由全域參數 multiMoldStrategy 決定採用哪一副（詳第 8 節）；使用者亦可手動指定模具。
  • 塞穴聯動：妥善穴數減少時，單穴克重自動上升（流道重量由更少穴數分攤），且日產能同時下降——此為數學自動聯動，非人為估算。
  • Anti-Placebo 保護：BOM 缺 std_mfg_scrap_rate 即擋下計算並提示補值（0 為合法值，不會誤判為缺值）。

Phase 3｜原料淨需求與採購建議#

虛擬預扣 KG = WIP待驗量 × 單穴克重 ÷ 1000 ÷ Max(0.01, 1 − 損耗率)　（僅當 enableVirtualBackflush 開啟） 有效原料在庫 = Max( 0 , 帳面在庫 − 虛擬預扣 ) 原料淨需求 KG = Max( 0 , 毛需求 − 有效在庫 − 在途量 + 安全庫存 × safetyStockMultiplier ) 建議採購量 KG = ⌈ 原料淨需求 ÷ MOQ ⌉ × MOQ　（無條件進位至最小起訂量倍數） 最晚下單日 = 需求交期 (target_date) − 採購交期 lead_time_days 距最晚下單日天數 = 最晚下單日 − 今天　（負值代表已逾期）
  • 虛擬預扣（Virtual Backflush）：廠內自製半成品於月內已成型但 ERP 月底才開單扣料，造成帳面原料虛增。開啟後系統先行預扣 WIP 已耗用之原料，消除「月中庫存高估」的時序差。
  • 安全庫存、MOQ、採購交期皆取自品號主檔中該原料品號（RAW 類）自身欄位，缺任何一項即拒絕計算採購建議。

19設計原則：零偽造與缺值即擋

  • 缺值即擋，禁止靜默預設：主檔關鍵欄位（良率、損耗率、交期、MOQ、安全庫存）缺值時，引擎拒絕計算並明確指出缺哪些欄位，絕不偷偷代入預設值讓數字看起來正常。
