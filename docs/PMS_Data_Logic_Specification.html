本系統以「訂單與預測」為起點，經三階段展開至原料採購建議，並同步進行庫存折算、產能驗證與風險預警。整體資料流如下：

  • 五大資料主檔：item_master（品號主檔）、mold_master（模具主檔）、product_mold_bom（成型 BOM）、inventory_wip_snapshot（庫存/WIP 快照）、po_in_transit（在途採購單）。
  • 兩大需求來源檔：demand_forecast_log（業務預估需求，含版本號 version_no）、actual_order（實際客戶訂單）。
  • 四大運算引擎：MRP 引擎、WIP 日推估引擎、訂單缺料分析引擎、需求交叉比對引擎；另含資料完整性掃描器與端到端模擬測試套件。

02需求彙總邏輯（四種模式）

系統將「客戶預估（Forecast）」與「實際訂單（PO）」合併為總需求時，由全域參數 demandConsumptionMode 決定彙總方式：

模式代碼運算式說明與適用情境
additive（預設）總需求 = 預估量 + 實單量預估視為尚未下單之未來需求，與已下單量累加。保守備料，適合客戶「預示＋分批落單」型態。
po_consume總需求 = Max(預估量, 實單量)實單自預估中沖銷（消耗），取兩者較大者。適合「預估為總額上限、訂單逐筆吃掉預估」的客戶。
actual_only總需求 = 實單量完全只信賴實際訂單，忽略預估。
forecast_only總需求 = 預估量完全只信賴客戶預估，忽略實單。
補充：所有 MRP 計算均排除已取消（cancelled）狀態之訂單；在途 PO 亦排除已到達（arrived）與分批到達（partial_arrived）狀態，避免重複計入可用供給。

03三階 MRP 核心引擎（成品 → 模具 → 原料）

MRP 引擎（mrpEngine.ts → calculateMRPForSKU）針對單一成品 SKU，依最新（或指定）版本之預估需求執行三階段推導：

Phase 1｜成品淨需求（FG Net Requirement）#

WIP 有效量 = WIP 待驗量 × 標準全檢良率 (std_sorting_yield) 成品淨需求 = Max( 0 , 總需求量 − 成品良品在庫 − WIP 有效量 )
  • 總需求量依第 2 節之四種彙總模式決定。
  • 良品在庫與 WIP 待驗量取自最新日期之庫存快照。
  • Anti-Placebo 保護：若品號主檔缺 std_sorting_yield，該 SKU 直接回傳紅色「無法計算」警示，禁止靜默帶入預設值偽裝成有效運算。

Phase 2｜BOM 展開與原料毛需求#

單穴克重 Unit_Weight_g = ( 整模淨重 net_mold_weight_g + 流道重 runner_weight_g ) ÷ 妥善穴數 active_cavities 原料毛需求 KG = ( 成品淨需求 PCS × 單穴克重 g ÷ 1000 ) ÷ ( 1 − 成型損耗率 std_mfg_scrap_rate )
  • 一個成品可能綁多副模具（多筆 BOM），由全域參數 multiMoldStrategy 決定採用哪一副（詳第 4 節）；使用者亦可手動指定模具。
  • 塞穴聯動：妥善穴數減少時，單穴克重自動上升（流道重量由更少穴數分攤），且日產能同時下降——此為數學自動聯動，非人為估算。
  • Anti-Placebo 保護：BOM 缺 std_mfg_scrap_rate 即擋下計算並提示補值（0 為合法值，不會誤判為缺值）。

Phase 3｜原料淨需求與採購建議#

虛擬預扣 KG = WIP待驗量 × 單穴克重 ÷ 1000 ÷ Max(0.01, 1 − 損耗率)　（僅當 enableVirtualBackflush 開啟） 有效原料在庫 = Max( 0 , 帳面在庫 − 虛擬預扣 ) 原料淨需求 KG = Max( 0 , 毛需求 − 有效在庫 − 在途量 + 安全庫存 × safetyStockMultiplier ) 建議採購量 KG = ⌈ 原料淨需求 ÷ MOQ ⌉ × MOQ　（無條件進位至最小起訂量倍數） 最晚下單日 = 需求交期 (target_date) − 採購交期 lead_time_days 距最晚下單日天數 = 最晚下單日 − 今天　（負值代表已逾期）
  • 虛擬預扣（Virtual Backflush）：廠內自製半成品於月內已成型但 ERP 月底才開單扣料，造成帳面原料虛增。開啟後系統先行預扣 WIP 已耗用之原料，消除「月中庫存高估」的時序差。
  • 安全庫存、MOQ、採購交期皆取自品號主檔中該原料品號（RAW 類）自身欄位，缺任何一項即拒絕計算採購建議。

大宗採購分批到貨排程（Phased Delivery Advisor）#

當 enablePhasedDeliveryAdvisor 開啟且建議採購量屬大批次（大於倉容上限 × 0.6，或 ≥ 5,000 KG）時，自動拆為兩批：

首批量 = ⌈ 建議量 × 50% ÷ MOQ ⌉ × MOQ　｜ 到港日 = 需求交期 次批量 = 建議量 − 首批量　　　　　　　　　　 ｜ 下單日 = 首批下單日 + 30 天；到港日 = 需求交期 + 30 天 目的：防範實體爆倉與降低資金積壓。

04射出產能與模具參數邏輯

日產能 PCS = ( 每日運轉秒數 ÷ 成型週期 cycle_time_sec ) × 妥善穴數 active_cavities 每日運轉秒數 = dailyOperatingHours × 3600　（預設 24h = 86,400 秒） 所需生產天數 = ⌈ 成品淨需求 ÷ 日產能 ⌉ 交期餘裕天數 = 需求交期距今天數 − 所需生產天數 − capacityBufferDays　（負值 → 觸發產能瓶頸紫色預警）

多模備料策略（multiMoldStrategy）#

策略代碼選模規則業務意涵
conservative_max_weight（預設）選「單穴克重最重」的模具保守原則：按最耗料情境備料，確保不缺料，寧多勿缺。
lowest_weight選「單穴克重最輕」的模具精實原則：按最省料情境備料，降低庫存資金積壓。
primary_mold_only僅採用標記為主模（is_primary_mold）之 BOM固定主力模具生產，其餘模具不納入備料考量。

塞穴告警門檻（cavityAlertThresholdPercent）#

當「妥善穴數 ÷ 設計穴數」低於設定百分比（預設 100%，即任一穴停用立即提醒）時，系統提示塞穴維修警告；塞穴同時會使單穴克重膨脹、日產能下降（見第 3 節聯動關係）。

06色母／色粉配色製程拆分邏輯

當 BOM 之 color_mixing_ratio_pct > 0 時，BOM 的 rm_sku 代表色母品號，總毛需求需拆分為「基礎樹脂」與「色母」兩條獨立的淨需求與採購建議：

有效基礎樹脂毛需求 KG = 總毛需求 ÷ ( 1 + 配比 % ÷ 100 ) 色母毛需求 KG = 總毛需求 − 有效基礎樹脂毛需求 樹脂淨需求 = Max( 0 , 樹脂毛需求 − 樹脂在庫 − 樹脂在途 + 樹脂安全庫存 ) 色母淨需求 = Max( 0 , 色母毛需求 − 色母在庫 − 色母在途 + 色母安全庫存 ) 兩者各自依 MOQ 向上進位產出獨立採購建議。

範例：總毛需求 51.0 KG、配比 2.0% ➜ 樹脂 51.0÷1.02 = 50.0 KG、色母 = 1.0 KG。

訂單缺料分析中的簡化式：在訂單緊張度診斷（第 8 節）中，色母毛需求改以 總毛需求 × 配比 ÷ (100 + 配比) 快速推估，並與有效樹脂在庫比較以判定藍色「色母缺料」環節。

07WIP 在製品日推估引擎

WIP 引擎（wipEngine.ts → calculateDailyWIP）模擬「機台 24 小時成型 vs 白班約 12 小時人工挑選」的現場時序差，逐日推估在製品暫存區結存：

當日理論產出 P(t) = 工時 × ( 3600 ÷ 成型週期秒 ) × 妥善穴數 × ( 1 − 不良率 ) WIP(t) 結存量 = Max( 0 , WIP(t−1) 前日結存 + P(t) − S(t) 當日全檢完工入庫量 ) 夜班積壓量 = ( P(t) ÷ 工時 ) × Min( 12 , 工時 )　（20:00~08:00 無人挑選時段之產出） 當日原料耗用 KG = P(t) × 單穴克重 ÷ 1000 ÷ Max( 0.01, 1 − 不良率 ) 預估暫存箱數 = ⌈ WIP(t) ÷ 3,500 PCS/箱 ⌉

FIFO 庫齡警示門檻#

暫存箱數警示燈號意涵
≤ 150 箱fresh 正常週轉健康，先進先出秩序正常。
> 150 ~ 300 箱warning 注意堆存量偏高，應加速全檢去化。
> 300 箱critical 危急暫存區逼近飽和，須立即拉高挑選能量。

08訂單缺料分析（訂單緊張度診斷）

缺料分析引擎（orderTensionEngine.ts → diagnoseAllOrderTensions）對每一筆有效訂單逐一檢查六大瓶頸環節，並綜合評定緊張等級。清單預設按緊張度由高至低排序。

六大環節與觸發條件#

環節燈號觸發條件
① 原料採購交期red 紅原料淨需求 > 0 且 距最晚下單日 ≤ shortageAlertBufferDays（負值＝下單已逾期）
② 模具射出產能purple 紫所需生產天數 > 距交期天數（產能赤字）；或模具狀態為 maintenance 維修中
③ WIP 待驗品yellow 黃成品現貨不足，但「現貨＋有效WIP」足夠 ➜ 需仰賴及時全檢
③′ WIP 待驗品red 紅「現貨＋有效WIP」仍不足 ➜ 實質缺貨赤字，須緊急開機或協調延後交貨
④ 在途海運船期orange 橘存在狀態為 delayed 之在途 PO（船期延誤風險）
⑤ 色母配色缺料blue 藍配比 > 0 且 色母需求量 ＞ 有效樹脂在庫
補充：「實體倉容超載」不屬於逐單診斷環節，由 MRP 引擎在原料品號層級監控——(在庫＋在途) ＞ defaultWarehouseCapacityKg（預設 12,000 KG）時發出橘色爆倉預警（詳第 14 節）。

綜合緊張指數評定（tensionScore, 0~100）#

任一環節為 紅(red)　　　　　　 ➜ critical 危急　score = 95 否則有 紫(purple) 或 橘(orange) ➜ high 高度　 score = 75 否則有 黃(yellow) 或 藍(blue)　➜ medium 中度　score = 50 皆無　　　　　　　　　　　　　 ➜ normal 正常　score = 10
主檔缺值優先攔截：若訂單品號缺「標準全檢良率」、BOM 缺損耗率或原料缺採購規則，系統強制在診斷結果最前方插入「⚠️ 主檔缺值」紅色項目，並標明本單診斷數字不可作為決策依據。

09需求三向交叉比對（預測 vs 實單 vs 歷史同期）

需求比對引擎（demandAnalysisEngine.ts → analyzeDemandCrossComparison）針對有客戶需求之品號（PART / COMP / SET 類），按需求交期逐期比對三方數量：

差值 = 實際訂單量 − 客戶預估量 偏差率 bias% = ( 實單 − 預估 ) ÷ 預估 × 100%　（無預估卻有實單 ➜ 插單，bias = +100%）

警戒門檻#

|偏差率|燈號意涵
≤ 10%normal 綠需求平穩符合預期。
> 10% ~ 25%warning 黃中度偏差，列入週二出貨會議追蹤。
> 25% 或 插單critical 紅正偏 ➜ 突發插單斷料高危；負偏 ➜ 原物料呆滯庫存風險。

趨勢訊號判定#

  • 總偏差率 > +20% ➜ surging 需求竄升；< −20% ➜ shrinking 需求萎縮。
  • 任一期別出現紅色警戒 ➜ volatile 劇烈波動；其餘 ➜ stable 平穩。
歷史同期參考量的透明化說明：目前系統尚無歷史銷售實績表，畫面上的「歷年同期參考量」係以預估量 × 0.92 生成之推估基準軌跡，僅供相對比較，非真實歷史數據。此為已知待討論項，建議與業務單位確認是否導入真實歷史資料源。

10出貨排程放行（Ship Clearance）邏輯

出貨排程清理檢視（ShipScheduleClearanceView.tsx）以未來 14 天為窗期，逐品號判定能否如期放行出貨：

排程量 = 未來 14 天內有效訂單總量； 　　　　 若 2 週內查無訂單 ➜ 取最新版預估量 × 50%（月度預估換算雙週基準）。 總可用供給 = 成品良品在庫 + WIP 待驗量 × std_sorting_yield （主檔缺良率時，WIP 以 0 折算——保守不予認列，補值後自動恢復。）
判定條件狀態行動指引
良品在庫 ≥ 排程量clear 可放行成品庫存充足，可直接放行 100% 出貨。
良品在庫 < 排程量 ≤ 總可用供給wip_dependent 仰賴WIP須於出貨日前完成 (排程量 − 在庫) 之 WIP 全檢入庫。
總可用供給 < 排程量deficit 赤字實質缺口 = 排程量 − 總可用供給，須協調減量出貨或緊急加開產能。
  • 畫面提供 What-If 模擬倍率，可即時調整各品號排程量觀察放行狀態變化。
  • KPI「放行率」= (可放行 + 仰賴WIP 品項數) ÷ 總品項數 × 100%。
  • 業務工作台之「週二放行概況」採同一折算邏輯（覆蓋率 = (在庫覆蓋+WIP需求) ÷ 訂單總量），惟其良率預設顯示基準為 0.95。

類型嚴重度內容
外鍵斷鏈 broken_fkcriticalBOM 的 sku / rm_sku / mold_id、訂單與預測的 sku、快照 sku、PO 的 rm_sku 不存在於對應主檔。
孤兒資料 orphan_datainfo / warning未被任何 BOM 綁定的閒置模具；無訂單/預測/BOM 關聯之孤兒品號；訂單品號未建 BOM 無法 MRP 爆炸。
冗餘資料 redundant_datawarningBOM 重複複合主鍵 (sku+mold_id)。

主檔缺值 missing_fieldwarningRAW 類缺採購交期/MOQ/安全庫存；成品類缺標準全檢良率 ➜ 相關引擎將拒絕計算。

健康評分公式（Health Score, 0~100）#

健康分數 = 100 − 斷鏈錯誤數 × 15 − 一般警告數 × 2 − 未通過引擎數 × 20 鏈路健康 isChainHealthy = (斷鏈錯誤數 = 0 且 四大引擎流水線全部貫通)

引擎流水線貫通測試包含：MRP 引擎、WIP 引擎、訂單缺料分析引擎、出貨清理模組共四項。

12全域系統參數總表（可調）

15設計原則：零偽造與缺值即擋

  • 缺值即擋，禁止靜默預設：主檔關鍵欄位（良率、損耗率、交期、MOQ、安全庫存）缺值時，引擎拒絕計算並明確指出缺哪些欄位，絕不偷偷代入預設值讓數字看起來正常。
  • 空值呈現真實空狀態：查無資料時顯示 0 筆／無資料，不偽造數值。
  • 推估值必須標示：凡屬模擬推估（如未下單品號之推估交期、歷史同期參考軌跡），畫面明確標示其性質，不誤導使用者。
  • 資料去識別化：演練與種子資料一律使用 A客戶/B客戶/C客戶、A供應商/B供應商/C供應商 及去識別化單號格式，不含任何真實往來對象名稱。
  • 術語標準化：介面與本文件統一使用「原料倉庫／在製品待驗區／成品倉庫」等通用供應鏈術語，聚焦物料流與狀態流。
